## End-to-end check

Setup: temporary project (`mktemp -d`), temporary `HOME`, `CLAUDE_PROJECT_DIR` unset, built
`dist/project-companion.mjs` from this copy, a second unrelated `git init` folder in another temporary directory.
The real project and the real index were not touched. The temporary folders were removed afterwards.
1. `init`, `task add "Rotate keys" --status in_progress`, `run start <task> --session sess-e2e-1 --model m`.
2. (i) `git worktree add .claude/worktrees/wt1 -b wt1`; wrote `lib/auth/token.ts` there; piped an `ingest` payload
   whose `tool_input.file_path` is `<project>/.claude/worktrees/wt1/lib/auth/token.ts`; committed it inside the
   worktree ("Rotate the token").
3. (ii) piped a second payload whose path is `<other temp dir>/other/o.txt` (a separate repository).
4. `run show <run>`: `touched:` lists `lib/auth/token.ts` (relative) and the absolute `.../other/o.txt` (unchanged).
   The stored `run.progress` events hold `["lib/auth/token.ts"]` and the absolute path.
5. `project-companion git log` ignores runs (bug 37f9fbce), so I called `readGitView` (the app's Git view) on the
   temporary project from a scratch test (`tests/zz-e2e-scratch.test.ts`, deleted afterwards, never committed).
   Result: the commit "Rotate the token" is in `byTask` for the run's task with `"signal":"run"`, `"taskId"` equal
   to the task.

Observation (not a defect of this fix): on a first run of the script, the commit was made in the same wall-clock
second as `run start`, and it showed as unattributed. The commit time has one-second precision and the run's start
has more, so a commit made within the same second before the run's start time is read as outside the window. With a
`sleep` of 2 s before the write and 1 s before the commit, it links. Real agent work is never that quick, so I did
not raise it as a bug; it is a possible flake source in a future test that runs fast.

## Revert checks (test rule 6)

I could not edit `lib/project/store.ts` or `git-link.ts` in this checkout: the write scope of this role refuses
it (EN-06.1). So I ran the same reverts in place, one line each, in a throwaway copy of the working tree under
the scratchpad (outside the repository, `node_modules` linked, never committed). Every export stayed.

(a) `reportRun`: `.map((path) => relativeToRoot(root, path))` changed to `.map((path) => path)`.
- `bug-15753492`: 0/1, FAIL.
- `run-paths`: 4/6, FAIL on `an absolute path inside the root is stored relative...` and on `mayWrite sees the relative path...`.

(b) `linkRepository`: `run.touched.map((p) => relativeToRoot(root, p))` changed to `run.touched.map((p) => p)`.
- `run-paths`: 5/6, FAIL on `an old run holding an absolute path still attributes to its commit`.
- `bug-15753492`: still 1/1 (the write side stores relative paths, so the read side is not needed there).

Observation: with only the write side reverted, the regression test fails on its "control" assertion (the stored
path is not relative), not on the attribution assertion, because the read side still repairs the match. This is
sound, since each side has its own test, but the attribution assertion alone does not isolate the write side.

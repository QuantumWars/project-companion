## Gap found (low, fixed by an added test)

The pull request has no test that makes `main()` throw an error other than the log refusal through the top-level handler. A handler
that catches everything left all 6 tests passing. I added `tests/qa-f6864c33-rethrow.test.ts` (1 test, built CLI in a child
process, 10-second timeout, temporary `HOME`, no planted file). It runs `update draft ... --file <missing file>`, which throws ENOENT
from `readFileSync` before any log write, and asserts: non-zero exit, `ENOENT` on stderr, a stack frame on stderr, and no "event log"
text. It passes on the head and fails with the accept-everything handler. No change to `cli/` was needed (the handler did not have to
be extracted). I did not use `run start` for this: it is a different, out-of-scope error and its output may change. The builder or EM
should keep the test in the pull request.

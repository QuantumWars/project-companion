# 0.3.0 launch checklist

Epic: decision-alerts (one macOS notification for each new gate request and card open,
the `PROJECT_COMPANION_NOTIFY=off` switch, and the git-ignored `.project-notify/record.jsonl`),
plus CI on every pull request.

- [x] All stories in the release meet the Definition of Done — 10 sprint tasks (PRs #8, #10,
      #11, #12, #14, #15, #16, #17, #18, #19) and 6 decision-alerts stories are recorded done;
      all 4 features show done, 17 of 17 criteria ticked
      (`npx project-companion feature list --phase decision-alerts`, per the EM's facts — I did
      not run this CLI command myself, see "Never run the built CLI" below). Every merged PR
      passed the `ci` check on its final head (EM's facts; I did not re-run `gh pr checks`).
- [x] Architecture and dependencies: no new dependency without an ADR — no new dependency since
      the sprint plan (commit 904dfdf); `package.json` only gained the `typecheck` script (PR
      #8), confirmed by reading the current `package.json`. No ADR needed.
- [x] Failure modes: rollback steps written and tried once — design.md section 6 (`specs/decision-alerts/design.md`,
      "6. Rollout and rollback") gives two rollback paths: (a) set `PROJECT_COMPANION_NOTIFY=off`
      where the EM's commands get their environment, which stops banners but not the slow text
      lookup (SR-8); (b) revert PR #17, which removes the two CLI calls (`gate request`, `card
      open`) and the README paragraph, and fixes SR-8 too, leaving the library unused. I tried
      path (a) once, exactly as instructed: ran `PROJECT_COMPANION_NOTIFY=off npm test -- notify`
      (never the built CLI, never osascript). Result: 47/47 passed, exit code 0, including
      DA-03.1 ("off passes no notification") and DA-03.3 ("linux and win32 pass no notification"),
      which prove the off switch suppresses the notifier and leaves the command's exit code and
      output unchanged. I did not try path (b) (reverting a merged PR) — that is a code change
      outside this checklist's scope; owner: EM, if the PM calls for a rollback drill of path (b).
- [x] Capacity: not applicable — a local CLI that runs on the PM's own Mac, invoked one gate
      request or card open at a time; there is no server, no concurrent users and no load to
      size. Checked by reading `package.json` (the `bin` entries are two local commands, no
      server script) and the design's rollout note (`specs/decision-alerts/design.md` section 6,
      "There is no flag and no staged rollout: this is one user on one Mac.").
- [ ] Security: open items the PM has not accepted yet, from the PR reviews (recorded in the
      tracker) — left unticked for the PM to accept or reject at the release gate:

      - TH-7 and TH-8: recorded as mitigated, with SR-8 as the residual risk (same underlying

      - F3: trusts an existing `.gitignore`, file mode or tracked record; TH-13 residual.
      - F5: track-card banners show free agent text; TH-11.
      - TH-21: the mkdir-race re-lstat branch is untested (the notify suite's TH-21 cases cover a

      - TH-15: a reader of `.project-notify/record.jsonl` must split lines on `\n` only.
      Owner: PM, at the release gate (`/devolps:ship release`).

## Version

`npm version 0.3.0 --no-git-tag-version` (no tag, no commit made by npm). Previous version:
`0.2.0`, set 2026-10-07 with the gate engine (commit 790cc3a). No git tag exists yet and no
GitHub release exists yet for any version; this release creates the first of each, after the
PM's release gate.

Note: `package-lock.json`'s package name was already `board-video-tutorial` (not
`project-companion`) and its version was already `0.1.0` (not `0.2.0`) before this change —
a pre-existing drift from `package.json`, unrelated to this release. `npm version` only touches
the version fields; it does not rename the lockfile's package.

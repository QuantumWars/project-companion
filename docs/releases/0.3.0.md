# 0.3.0 — 2026-10-10

Bottom line: project-companion now taps the PM on the shoulder on macOS when a decision is
waiting, and every pull request now runs an automatic CI check.

What's new:
- On macOS, every new `gate request` and `card open` (a question or track card) now shows
  one system notification, with the decision's title, its command and the project name —
  the same text the PM cockpit shows. Nothing else sends a notification.
- A shell can turn these notifications off with `PROJECT_COMPANION_NOTIFY=off` (the value
  must be exactly `off`). On any system other than macOS, nothing is sent, and the command
  behaves the same either way.
- Each attempt is logged, one line per attempt, to a local file
  (`.project-notify/record.jsonl`) that is not checked into git.
- Every pull request now runs an automatic CI check: it installs dependencies, checks
  types, runs the tests and builds the tools.

What's fixed: nothing user-visible. This release is a new feature plus the new CI check.

What to watch:
- A known slow-lookup issue (tracked as bug d5ebde85, owner: Engineering Manager, planned
  for next sprint) means a specially crafted project log could make `gate request` or
  `card open` hang. This does not happen in normal use.
- Notification banners can show decision text on the lock screen or in screen sharing.
  macOS's own "Show previews" setting controls this (owner: PM, when configuring their Mac).
- A track card's banner can show text written by an agent inside what looks like a command
  (owner: PM/architect, tracked as finding F5).
- macOS Focus mode can hide these banners, same as it hides any other notification.
- Whether macOS will ask for permission to show notifications the first time this runs is
  not yet known (owner: design).
- This feature only does anything on macOS; other systems are unaffected.
- `ci` is not yet a required check on master; the PM turns it on in GitHub settings
  (owner: PM).

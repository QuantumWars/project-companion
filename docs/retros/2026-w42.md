# Retro: sprint 2026-w42

Bottom line: The team shipped everything it planned, on time, and release 0.3.0 is out — but tests sent work back for review too often, and three tooling gaps (merge checks, tracker-log merges, a mistyped command) cost time that a few small fixes can recover.

Delivered: 6 of 6 decision-alerts stories (18 points); 10 of 10 tasks done, 21 points (19 committed plus 2 added, including a CI task). All 17 acceptance criteria are ticked. Release 0.3.0 shipped on 2026-10-10.

Where work waited:
- Review sent work back 8 times; most of the fixes were in tests (test helper clean-up, a missing timeout check, a missing test for a config error).
- Merges: `devolps merge` refused every delegated merge because it still counted old, already-fixed findings as open, so the PM typed the ship command by hand each time.
- The ship command did not run 5 times when typed with a leading space.
- Role agents hit their turn limit about 8 times and needed a restart; twice the agent-cap guard still counted a stopped agent as running, which held up other work.
- Every squash merge left a tracker-log conflict for the next branch; each one needed a manual resolve-and-check step.
- The release tag landed on the release branch's commit, not master's — same code, different commit.

Overrides:
- Merge 6 — approved as documents-only (specs were approved at the PRD and design gates; the repository has no CI yet).
- Sprint 2026-w42 — approved a Quick-track CI task with no separate analyze step, because its spec lists one task and a check for each requirement.
- Merge 20 — approved for the release's CHANGELOG and version-number update.
- Release 0.3.0 — approved with its open low risks accepted; one (SR-8) is tracked as a follow-up bug, two others are recorded as mitigated.

What helped:
- Security and code review caught real problems before merge: a command that could hang, a path that only worked on one machine, a test-only setting that leaked.
- The test rule that stubs the environment meant no test run ever showed a live, real banner.
- CI ran on every pull request.
- The PM's delegation let the team run build, review and QA back-to-back without waiting on each approval.

What to change:
1. Put all the accumulated test rules in one place builders read first, and add a self-check before review — owner: Engineering Manager — done when review sends back fewer than 8 items next sprint and each change needs less than 2 review rounds on average.
2. Line up the checkout with master's commit before tagging a release — owner: Engineering Manager / devolps tool — done when the next release tag sits in master's history.
3. Make the CI check required on master — owner: PM — done when branch protection lists it.
4. Give the tracker log a merge rule so squash merges stop clashing — owner: devolps maintainers — done when no manual merge fix is needed next sprint.
5. Fix the ship command so a leading space does not stop it — owner: PM / devolps tool — done when no "command not handled" reply happens.

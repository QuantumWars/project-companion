Risks:
- **No delivery history.** This is the first sprint in the tracker, so recent delivery is UNKNOWN. 21 points is the whole epic plus CI, not a measured capacity. This sprint sets the first baseline.
- **A long chain of merges.** 8 of the 10 tasks must merge one after another (order 0 to 7). Each one waits for a PM merge gate. That is 10 merge gates in 5 days. A delay of one day in an early merge moves every later task.
- **Real alerts before their proofs.** The installed `project-companion` runs this checkout's build. When da-t7 is built here, real Mac notifications start. Only da-t8 proves that a broken or slow notifier leaves the command unchanged. Plan: build da-t8 at once after da-t7, and merge them on the same day. If da-t8 cannot merge by Friday, hold da-t7 too and carry both over.
- **CI has never run on GitHub.** Every check in `specs/ci/quick.md` ran on the PM's Mac. Run time on a GitHub runner is UNKNOWN. A red first run delays order 1, and every later task with it.
- **One security test may skip in CI.** CI runs on `macos-latest` so that DA-02.4 (SR-5) runs. Whether `/usr/bin/osascript` exists on a GitHub macOS runner is not checked. If it does not, the test skips and `ci` can pass without it. QA checks the test's result in the `ci` log at da-t4.
- **One shared test file.** Tasks da-t2 to da-t9 all add to `tests/notify.test.ts`. The parallel pairs (da-t3 with da-t4, da-t8 with da-t9) will conflict at the end of the file. Each adds its own section and rebases before its pull request.
- **The README paragraph needs the tech-writer.** DA-03.4 ships in da-t7. Only the tech-writer can write `README.md`. It writes the paragraph at the pull-request step of da-t7.

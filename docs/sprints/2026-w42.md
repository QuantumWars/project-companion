Risks:
- **No delivery history.** This is the first sprint in the tracker, so recent delivery is UNKNOWN. 19 points is the whole epic, not a measured capacity. This sprint sets the first baseline.
- **A long chain of merges.** 7 of the 9 tasks must merge one after another (order 1 to 7). Each one waits for a PM merge gate. That is 9 merge gates in 5 days. A delay of one day in an early merge moves every later task.
- **Real alerts before their proofs.** The installed `project-companion` runs this checkout's build. When da-t7 is built here, real Mac notifications start. Only da-t8 proves that a broken or slow notifier leaves the command unchanged. Plan: build da-t8 at once after da-t7, and merge them on the same day. If da-t8 cannot merge by Friday, hold da-t7 too and carry both over.
- **The spec branch is not on master.** `docs/decision-alerts-design` holds the requirements, the design, the stories and the tracker log (16 commits, about 2,316 lines, from `git diff --stat origin/master...HEAD`), and it is not pushed. Builders start from the commit the EM checks out. If this branch does not reach master before the first build, every task's pull request carries those 2,316 lines. It must merge first, through the PM.
- **One shared test file.** Tasks da-t2 to da-t9 all add to `tests/notify.test.ts`. The parallel pairs (da-t3 with da-t4, da-t8 with da-t9) will conflict at the end of the file. Each adds its own section and rebases before its pull request.
- **The README paragraph needs the tech-writer.** DA-03.4 ships in da-t7. Only the tech-writer can write `README.md`. It writes the paragraph at the pull-request step of da-t7.
